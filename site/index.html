A linter for prose

Plainly reads Markdown and plain text and flags the habits of generated writing: the stock words, the throat-clearing, the "not just X, but Y", the bold-label bullets, the "In conclusion". It scores the page, fixes what is safe to fix, and runs in your pull requests.

    Why a linter, and not a detector

    Detectors guess whether a model wrote something and give you a percentage. Plainly does not care who wrote it. It points at the sentence and says what the habit is, why it reads as generated, and what to write instead. A person who writes "delve" four times gets the same note as a model that does, and both can act on it.

    None of the patterns is wrong on its own. People write "robust", use em dashes, and end with a summary. The tell is the density, so the score is for the page and the findings are for the sentence. Code blocks, inline code, URLs and front matter are never prose, and a word in quotes is a mention, not a use.

    The rules

    Every rule has a reason and an example. Three are opinions you opt into. The list below is generated from the code, so it cannot drift.

    Install and run

    pip install git+https://github.com/owaiskhalid-si/plainly

plainly                        # every .md, .mdx and .txt under the current folder
plainly docs/ README.md
plainly --fix docs/            # apply the safe fixes in place
plainly --diff docs/           # show them as a patch first
plainly --changed origin/main  # only what this branch touched
git log -1 --format=%B | plainly --stdin   # a commit message
plainly --format sarif -o plainly.sarif    # github, json, sarif, markdown
plainly rules                  # and: plainly explain tells/em-dash

    Configure it in plainly.toml or [tool.plainly] in pyproject.toml: which files, the score to fail under, words your project uses on purpose, rules to switch on or off, per-rule options and severities. plainly --write-baseline lets an old project adopt it without fixing every page first.

    include = ["**/*.md", "docs/**/*.txt"]
fail-under = 60
allow = ["robust"]
enable = ["clarity/passive"]

[rules."clarity/long-sentence"]
max-words = 40

    In your pull requests

    The GitHub Action annotates the changed lines, writes a score table to the job summary, and can send the findings to code scanning with one-click fixes.

    - uses: actions/checkout@v4
  with: { fetch-depth: 0 }
- uses: owaiskhalid-si/plainly@main
  with:
    changed-since: origin/${{ github.base_ref }}
    fail-under: "60"
    sarif: "true"

    There is a pre-commit hook too, and the same engine runs this page's demo as a small Python function.
